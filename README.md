# Messengers_Analyze

Проект предназначен для сбора, интеллектуального анализа и маршрутизации сообщений из различных чатов Telegram с помощью Telethon.

Все входящие сообщения сохраняются в базу данных с соответствующими метками и делятся на две основные категории:

1. **Срочные (Рабочие)** — командные чаты, рабочие группы и обсуждения, где требуется ваше непосредственное участие как исполнителя.
2. **Информационные** — рассылки, новости, статьи, каналы и т.д.

### Архитектура и логика обработки

- **Срочные сообщения (Real-time анализ):** Проходят немедленный анализ сразу после поступления. Из них извлекается информация о срочности, тегах, выделяются дедлайны и поручения.
- **Информационные сообщения (Batch анализ):** Сохраняются в течение дня и проходят ежедневный анализ на полезность. Скрипт **`daily_analysis.py`** на LangGraph + Groq фильтрует спам, классифицирует сообщения, пишет саммари и проверяет его качество (Critic-нода) перед сохранением в таблицу `analysis_results`. Запуск по cron или вручную.

### Технологический стек (Python)

- **Сбор данных:** `Telethon` (асинхронное взаимодействие с Telegram API в качестве юзербота).
- **База данных:** `SQLAlchemy` (ORM) +  `PostgreSQL` (для продакшена).
- **Оркестрация и воркфлоу:** `Apache Airflow` для ежедневных ресурсоемких задач (сбор инфо-постов за день и саммаризация). 
- **Взаимодействие с LLM:** `LangChain` / `LlamaIndex` + `OpenAI API` (или локальные модели через `Ollama`), использование структурированного вывода (JSON) для парсинга задач и дедлайнов.
- **Продвинутая логика и LLMOps:** **`LangGraph`** для создания сложных агентских циклов и пайплайнов (вместо линейных цепочек), и **`LangSmith`** для глубокого мониторинга, отладки промптов и оценки качества работы LLM.
- **Real-time обработка (Очереди):** `FastAPI` (для webhook-интерфейсов) и `Celery` / `Redis` для асинхронной обработки срочных сообщений без блокировки основного потока Telethon.

### Использование LangGraph и LangSmith в проекте

**LangGraph (Умные графовые workflow):**
*   **В Batch-пайплайне (Информационные чаты):** С его помощью можно построить «рефлексирующего» агента. Например, пайплайн превращается в граф: *Нода 1* фильтрует спам -> *Нода 2* группирует новости -> *Нода 3* пишет саммари -> *Нода 4 (Critic-агент)* проверяет саммари на наличие галлюцинаций и упущенных фактов. Если качество плохое, граф делает цикл (возвращает на доработку).
*   **В Real-time пайплайне (Рабочие чаты):** Если пришло "срочное" сообщение, граф-роутер решает, что с ним делать. Если в задаче не хватает контекста (например, написано "сделать к среде", но непонятно к какой), агент может пойти в RAG (перечитать предыдущие сообщения в базе) благодаря state-переменным, чтобы точно определить дату и только потом сохранить таску.

**LangSmith (Платформа отладки и мониторинга):**
*   **Трейсинг ошибок:** Анализ сложных шагов, если система пропустила важный дедлайн или ошиблась в теге (можно просмотреть все слои ответа модели и промпта).
*   **Оценка качества (Evaluation):** Создание датасета тестирования для проверки того, как качественно собирается утренний дайджест новостей при смене промпта или модели.
*   **Контроль затрат:** Точный мониторинг расхода токенов и времени ответов (Latency) для каждого этапа анализа отдельно.

### Быстрый старт с LangChain / LangGraph

Для пошагового изучения стека и реализации агента информационных чатов откройте **`guide.ipynb`** в корне проекта. Ноутбук содержит:

- Введение в LangChain (prompts, LCEL, structured output).
- Основы LangGraph (`StateGraph`, ноды, условные рёбра, циклы).
- Готового агента для информационных чатов: фильтрация → кластеризация → саммари → критик → доработка.
- Подключение к БД проекта (`database.py`) и сохранение дайджеста.
- Интеграцию с LangSmith и пример Airflow-DAG.

### Предположительный план реализации

План разделен на две основные фазы: сначала реализуется полноценная система агрегации информационных каналов, а затем к ней добавляется модуль мгновенной обработки срочных рабочих переписок.

#### Фаза 1. Полная система для Информационных чатов (Batch MVP)

**Этап 1. Базовая инфраструктура и сбор**
1. Настройка авторизации Telethon-клиента (сохранение `.session` файлов).
2. Проектирование схемы БД (Таблицы: `Chats`, `Messages`, `Tags`).
3. Создание скрипта-слушателя, который сохраняет сообщения только из разрешенных *информационных* чатов и каналов в базу данных.

**Этап 2. Внедрение Batch-пайплайна (LangGraph + LangSmith)**
1. Интеграция провайдера LLM и подключение **LangSmith** для логов, аналитики и оценки (evaluations) качества саммари.
2. Написание скрипта агрегации новостей за последние 24 часа.
3. Создание агента-пайплайна в **LangGraph**:
   - Нода фильтрации мусора и кластеризации новостей.
   - Нода генерации утреннего дайджеста.
   - Нода "Агент-Критик" (проверка дайджеста по заданным метрикам; цикличный возврат на доработку).
4. Интеграция пайплайна в направленный граф задач (DAG) в **Airflow** для запуска каждое утро.

**Этап 3. Delivery-уровень и Упаковка**
1. Разработка простого Telegram-бота для общения с системой и отображения дайджеста.
2. Написание `docker-compose.yml`, объединяющего базу данных, Airflow и Telethon-listener. Выкатка первой версии.

#### Фаза 2. Добавление модуля для Срочных чатов (Real-time)

**Этап 4. Расширение архитектуры**
1. Обновление схемы БД (Таблицы: `Users`, `Tasks`).
2. Добавление очередей (`Celery` / `Redis` + `FastAPI`) для асинхронной обработки сообщений без блокировки основного потока Telethon.

**Этап 5. Внедрение LLM-роутера и сборщиков задач**
1. Проектирование StateGraph в **LangGraph** специального для рабочих чатов.
2. Агент-роутер классифицирует каждое сообщение из рабочего чата: задача, обсуждение, игнор.
3. При нехватке контекста агент использует микро-RAG (идет в БД читать последние 10 сообщений переписки).
4. Воркер структурированно извлекает: *Суть*, *Дедлайны*, *Ответственных*.

**Этап 6. Уведомление и финальные интеграции**
1. Настройка немедленного алерта (бот присылает срочную задачу вам в личку).
2. Настройка внешних интеграций через `n8n` или напрямую (отправка структурированных карточек задач в Notion / Todoist / Jira/ Trello).
3. Добавление воркеров и очередей в `docker-compose` и финальный деплой платформы.

## 🚀 Как настроить и запустить (Этап 2: LangGraph + LangSmith)

### 1. Настройка ключей (.env)
Скопируйте файл-шаблон (если вы на Windows, можно просто скопировать файл в проводнике и переименовать в `.env`):
```bash
cp .env.example .env
```

Затем откройте `.env` любым текстовым редактором и добавьте ваши API ключи:
- **`GROQ_API_KEY`**: Получите бесплатный ключ на [console.groq.com/keys](https://console.groq.com/keys)
- **`LANGSMITH_API_KEY`**: Получите ключ на [smith.langchain.com/settings](https://smith.langchain.com/settings)

*(Трейсинг LangSmith включится автоматически для всего графа, если указан ключ)*

### 2. Установка зависимостей
Убедитесь, что у вас активировано виртуальное окружение, затем:
```bash
pip install -r requirements.txt
```

### 3. Проверка (Smoke Test)
Запустите скрипт быстрой проверки, чтобы убедиться, что ключи работают, LLM отвечает, и LangGraph пайплайн собирается корректно:
```bash
python smoke_test.py
```

### 4. Запуск тестов
Для прогона полной логики пайплайна (спам-фильтры, саммаризация, оценка качества):
```bash
pytest tests/ -v
```
**Важно:** Все ваши тестовые прогоны и вызовы LLM автоматически синхронизируются и появятся в веб-интерфейсе LangSmith (в проекте `messengers-analyze`). Там вы сможете посмотреть, сколько времени занял анализ, какие промпты были отправлены, и сколько токенов потрачено.
